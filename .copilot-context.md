# GitHub CoPilot System Context: romsync Engine

## Core Intent & Persona
You are assisting a professional software engineer building a highly optimized, local-first emulation orchestration framework. The project is implemented in **Go (Golang)** using **gRPC over HTTP/2** for device synchronization behind an **Nginx reverse proxy**. An optional, token-protected HTTP admin dashboard is embedded in the server. Avoid suggesting bulky infrastructure overhead (like VPNs, Tailscale, or Syncthing). Focus on strict performance, micro-sized binaries, robust error handling for intermittent networks, and programmatic concurrency.

## System Boundaries & Contract Rules

### Deployment Context
- The current central server runs Arch Linux.
- Current Batocera clients include an x86_64 TV mini PC and an arcade cabinet.
- Other target devices include Miyoo Mini Plus handhelds running OnionOS and an Apple TV 4K with an A15 Bionic processor.
- Keep the public README platform-oriented; retain deployment-specific hardware and server distribution details here.

### 1. Protobuf Interface Spec (`proto/v1/romsync.proto`)
The system follows a specific data-streaming structure:
- **ROM Syncing:** Uses a persistent server-streaming RPC (`WatchCatalog`) to broadcast metadata manifests down to connected edge systems. File transfers must use chunked byte arrays (`stream FileChunk`) via bidirectional or server-streaming RPCs to keep runtime heap allocation constant.
- **Save Synchronization:** Uses an explicit conditional check (`CheckSaveState`) evaluating structural sync operations (`UP_TO_DATE`, `SERVER_IS_NEWER`, `CLIENT_IS_NEWER`, `CONFLICT`) prior to initiating binary block payloads (`UploadSave` / `DownloadSave`).
- **Media Selection:** Registration can save asset preferences; approved devices can change them through `SetAssetPreferences`. `WatchCatalog` and `DownloadFile` support per-request overrides. An omitted selection uses saved preferences, falling back to composite-only; an explicitly empty selection disables media, not ROMs or textual metadata. Overrides must match between catalog and download requests.
- **Asset Contract:** Types are composite, boxart, screenshot, wheel/logo, marquee, fanart, video, and manual/guide. Media entries include `asset_type`, associated ROM `game_id`, and client-platform-relative `target_path`. Filtered game lists reference only selected, available assets; advertised checksums/sizes must match downloaded bytes. Logical catalog IDs do not include the server's `romsync-data` prefix.

### Repository and Server Implementation
- Keep server application, tests, scripts, and deployment examples under `server/`; shared protobuf definitions/bindings remain under `proto/` and `gen/`, with one root Go module. Future client implementations belong under `clients/`.
- Store state as filesystem data rather than introducing a database or heavy infrastructure. Save conflicts use latest completed upload wins with immutable historical backups.
- The admin dashboard uses a searchable, paginated game list and animated metadata detail pane, not a tile grid. Preserve click and Up/Down/Home/End navigation, selection on refresh, responsive layout, and reduced-motion support. Web artwork uses composites independently of device preferences.
- `.github/workflows/go.yml` runs Linux CI on pushes and pull requests: Go vet, installer shell syntax validation, race-enabled tests, and an optimized server build.

### 2. Storage System & Environment Invariants

#### Server ROMs and Generated Metadata
- Platform directories contain ROMs only. Future enrichment writes game lists, media, and intermediate exports under `<ROM root>/romsync-data/<platform>/`; this reserved folder is not a platform.
- Generated assets use `media/<profile>/<asset-type>/` beneath that platform's generated-data directory. Profile PNG bounds are 1280x960 for Batocera, 640x480 for Miyoo, and 1920x1080 for tvOS; preserve aspect ratio and never upscale. Copy videos/manuals unchanged using bounded buffers.
- Keep independent frontend assets separate from web composites. Skyscraper uses individual-media, separate-logo, and composite export passes; the separate Pegasus logo export avoids EmulationStation's wheel/marquee substitution.
- Existing platform-local generated files are left untouched and ignored by the new catalog. Do not automatically migrate or delete them; rerun enrichment and verify the new output before manual cleanup.
- Windows development uses native Go with Skyscraper in WSL via `-skyscraper-wsl Ubuntu-24.04`. Keep Skyscraper's private configuration, credentials, and resource cache outside the ROM tree and repository. Linux runs Skyscraper natively.

#### A. Batocera Profile (x86_64 Linux)
- **Immutable Core:** Root system is read-only. Tool binaries and data pools must reside strictly inside the writable user data zone: `/userdata/`.
- **Target Directories:** ROM paths parse relative to `/userdata/roms/[platform]/`. Metadata is scraped and parsed into local standard cache systems: `/userdata/roms/[platform]/gamelist.xml`.
- **UI Refresh Command:** Execute native shell command `batocera-es-reload` to signal internal metadata updates.

#### B. Miyoo Mini Plus Profile (OnionOS ARMv7)
- **Low Footprint Constraints:** Memory pooling and battery preservation are absolute priorities. Do not suggest persistent background listening daemons.
- **Transactional Core Execution:** Write short-lived CLI tools meant to be called explicitly before core startup and immediately after close event handlers inside individual core launcher paths (`launch.sh`).
- **Media Targets:** OnionOS UI reads from `/Roms/[platform]/miyoogamelist.xml`. Media payloads must be downsampled and output to exact resolution requirements (**640x480** or matching aspect-ratio constraints) in clean PNG layout formats.

#### C. Apple TV 4K Profile (tvOS Swift Interop)
- **Cache Eviction Defense:** Prevent tvOS system purges by ensuring sandboxed storage files are written into the app container's native `Documents` space.
- **Attribute Constraints:** Set file isolation keys on the target directories programmatically: `URLResourceKey.isExcludedFromBackupKey`.
- **JIT Limitations:** Heavy runtime compilation tricks are unavailable. Filter distribution manifests to exclude heavy emulation layers (PS2, GameCube) for tvOS targets while preserving standard vintage suites (up to PS1/N64/Dreamcast).

## Code Quality Requirements
- **Stripped Executables:** Ensure cross-compilation configurations consistently optimize for micro footprint requirements via `-ldflags="-s -w"`.
- **No In-Place Overwrites:** Any incoming save data mutation inside `romsync-core` must preserve historical snapshots (`/backups/`) using time-stamped filenames before committing tracking state changes.
- **Graceful Reconnect Modalities:** Client network connections must utilize robust exponential backoff retry logic to recover from unstable network conditions without application crashing.
